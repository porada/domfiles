# Validate Shell Changes

After editing, use the narrowest applicable validation scope:

1. Pass changed paths explicitly to the matching lint wrapper. Omit paths only when repository-wide validation is intended. Explicit paths bypass [default discovery and its pathname limits](../../../PROJECT.md#development-lint-wrapper-architecture). Explicitly pass paths that Git C-quotes. With no paths, file-oriented wrappers discover tracked files and non-ignored untracked files. The Fish wrapper restricts that inventory to `*.fish` files. The POSIX wrapper uses `*.sh`, `home/.local/bin/*`, and `home/.local/share/*` to include extensionless entrypoints and `domlib`. File-oriented wrappers skip non-files and symlinks.
2. For Fish, run `env PNPM_CONFIG_FROZEN_LOCKFILE=true PNPM_CONFIG_PM_ON_FAIL=error PNPM_CONFIG_VERIFY_DEPS_BEFORE_RUN=error pnpm run lint:fish <changed-fish-files>`. Include `home/.config/fish/local.fish` explicitly when it exists. The wrapper already runs `fish --no-execute`, so do not repeat that check.
3. For POSIX shell, run `sh -n -- <file>` for each changed file and `env PNPM_CONFIG_FROZEN_LOCKFILE=true PNPM_CONFIG_PM_ON_FAIL=error PNPM_CONFIG_VERIFY_DEPS_BEFORE_RUN=error pnpm run lint:sh <changed-posix-files>`. The wrapper supplies the complementary ShellCheck analysis. For POSIX hooks without hashbangs under `.hooks`, add `SHELLCHECK_OPTS=--shell=sh` to that command’s `env` assignments and pass the hook paths explicitly.
4. Check formatting for changed `.fish` and `.sh` files and extensionless Fish and POSIX shell scripts with hashbangs using `env PNPM_CONFIG_FROZEN_LOCKFILE=true PNPM_CONFIG_PM_ON_FAIL=error PNPM_CONFIG_VERIFY_DEPS_BEFORE_RUN=error pnpm exec prettier --check <changed-shell-files>`. The configured Fish plugin infers extensionless Fish scripts from their `fish` hashbang, so do not force `--parser fish`. For POSIX hooks without hashbangs under `.hooks`, run a separate invocation of the formatting command with `--parser sh` and only those hook paths. Verify every applicable policy invariant in this skill and its routed references, including `domlib` ordering, usage, and `$DOMFILES_*` coverage when relevant. Run `git --no-pager diff --check` and, when task-owned changes are staged, `git --no-pager diff --cached --check`. Inspect task-owned untracked files directly without staging them because Git diff does not include them.
