# Dependency Approval

Authorized commit preparation includes installing or reconciling project-prescribed dependencies, tools, and package manager versions needed by its checks and hooks. Use the established workflow, including configured lifecycle steps, without separate installation approval. Preserve explicit task restrictions and native build approvals, integrity checks, and trust controls. An agent-created declaration doesn’t authorize a new choice.

An authorized history operation may incorporate dependency declarations and lockfile changes already in its selected upstream history without separate dependency change approval. History integration alone does not authorize installation or execution, but a separately authorized workflow can cover prescribed acquisition. New dependency choices, including conflict resolutions that introduce them, remain subject to the entrypoint’s [dependency approval gate](../SKILL.md#establish-authorization). Sandbox and security requirements remain in force.
