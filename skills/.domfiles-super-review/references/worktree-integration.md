# Worktree Integration

## Choose the Local Destination

The outermost super command owns integration. Resolve the task branch and local destination at the start, carrying forward the user’s selection and the command’s defaults. For a standalone `super-review` in a linked worktree with a committed result planned and no destination selected, ask once whether to finish on the task branch or fast-forward a named local base. A read-only review or a review limited to uncommitted changes finishes in the task worktree.

For a separate base, identify the branch, its starting commit, and the checkout that would be updated, or the ref if checked out nowhere. At startup, check that the base can fast-forward from its recorded tip to the proposed task tip, or already contains the entire intended result. If the branches have diverged or further task commits would fork from behind the base, settle an authorized reconciliation or worktree-only endpoint before dependent review. Keep commits already reachable from the separate base intact when preparing or correcting the series. Establish authority for that destination and for every commit the fast-forward would bring in, including inherited work. Record the destination and affected paths with the unit’s review target, using the planned paths for pending work. Treat commits already accepted on the base’s verified upstream, or another baseline the user selected, as comparison history. Cover the remaining incoming commits, including unpublished inherited work and its interactions with the task. Reuse applicable clearance and obtain any remaining coverage within the approved scope. Delivery on the task branch alone needs no branch update.

## Check the Candidate Before Cold Review

When local integration is planned, compare the current base with its recorded commit before dispatching cold review. Verify that it can fast-forward to the candidate or already contains it. If a checkout would change, verify its binding, inspect its scoped status and diff, and check the incoming paths for obstructions, including untracked or ignored files. Raise any obstruction with its owner. Continue review in the task worktree while a checkout-only obstruction holds landing. Run the review against the prepared commits in the task worktree. Keep the destination and these checks in the coordinator’s record. Use the existing `cold-review` prompt and reviewer lifecycle.

If the base has moved, recheck the approved range, checkout, and current validation. Record the verified base tip for landing. If the base and candidate have diverged, retain the task result and resolve how to reconcile the branches before relying on review for integration. After authorized reconciliation, rerun affected validation and refresh affected review coverage on the resulting commits. For a cold review already in progress or cleared, follow `cold-review`’s **Continue After Changes** with the existing reviewer when available.

## Land the Reviewed Commit

After the selected stages clear, verify that the exact candidate contains every selected change, including pending edits from a peer-only review. Record those edits under existing commit authority and confirm that clearance still covers the result. If the complete result cannot be committed or covered, report the worktree result and hold the base update. Recheck the destination branch, checkout, ancestry, affected paths, and review coverage against the agreed update. If the base already contains the cleared tip, integration is complete. If the expected base changed, apply the same range and coverage checks before proceeding. Keep newer task-branch commits outside the update.

From the verified checkout on the base branch, run `git merge --ff-only --no-autostash --no-overwrite-ignore <cleared-tip>`. If the base is checked out nowhere, use `git update-ref refs/heads/<base> <cleared-tip> <expected-base-tip>`. Verify the resulting tip and scoped checkout status and diff. A fast-forward to the exact cleared commit preserves its review coverage. If the checkout binding has changed outside the approved effects or Git refuses the update, retain the result on the task branch and report both tips and the reason.
