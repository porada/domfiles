# Documentation Boundary Checks

Use these checks when an agent documentation change crosses routed or layered documentation surfaces. Apply the entrypoint’s canonical definition and secondary-role principle, then inspect only the applicable boundaries:

- **Agent documentation and human-facing writing:** Agent documentation contracts own meaning, normative force, authority, links, context footprint, and every structure that carries scope, order, routing, or another behavioral distinction. `skill-development` adds the skill-specific metadata and portability contracts. `human-facing-writing` owns wording, reading path, cohesion, tone, prose conventions, and presentation-only changes to headings, paragraphs, lists, and local grouping. Preserve the agent documentation contract when the workflows conflict.
- **Entrypoint and reference:** A reference must not merely paraphrase its parent entrypoint’s applicability or routing.
- **Generic and specialized workflows:** A specialized workflow must begin at its domain-specific divergence and route back to the generic lifecycle rather than repeating that lifecycle. A routed validation section inherits the parent workflow’s generic checks and lists only checks whose inputs, execution context, or observable result are specific to that surface. As an ownership test, remove each specialized rule’s domain-specific nouns and constraints. If the remaining instruction still applies to sibling routes, the parent entrypoint owns it. When the specialized copy is more complete, promote the complete rule before removing the duplicate.
- **Rule, procedure, and diagnostic:** A workflow may define a normative rule, a procedure may operationalize it, and a rubric may translate it into observable review evidence. Treat these as distinct roles when each secondary occurrence contributes only the action, sequencing, condition, or diagnostic needed at that surface. Shared terminology alone is not duplication. Treat a secondary occurrence as redundant when it restates the rule without adding a route-specific action, condition, or observation.
- **Shared decisions:** When two routed workflows affect the same output decision, the entrypoint must assign each workflow a distinct abstraction level and terminology. A specialized reference may constrain an inherited decision, but it must not claim the same term or level as another route. When a specialized layer changes only the representation of inherited semantic values, refer to the inherited category and define only the transformation. Do not repeat concrete values merely to demonstrate that transformation.
- **Output contract and template:** A template must not restate directives already established by its output contract.
