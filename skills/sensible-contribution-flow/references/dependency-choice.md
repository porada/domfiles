# Dependency Choice

For a new dependency or tool choice, identify the exact smallest sufficient set and required features. Prefer existing dependencies or standard library capabilities. Before requesting approval, explain each dependency’s consumers, declaration and installation locations, purpose, and why existing capabilities or a custom implementation are insufficient. Disclose material licensing, runtime, supply chain, and version implications.

When selecting a new dependency or tool version, choose the newest stable release compatible with the project’s declared constraints, and explain an intentionally older release or pin. For an approved dependency change, follow repository version conventions without repeating selection or approval.
