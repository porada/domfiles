# Revise Existing Pull Requests

Resume from the existing pull request and contribution branch rather than restarting the initial proposal. Record the pre-revision state as the review baseline, resolve current [scope and authority](../SKILL.md#resolve-scope-and-authority), and apply the [checkout and setup access checkpoint](prepare-pull-requests.md#enter-supplied-checkout) under that authority. Preserve the published branch name and title unless the current request covers changing them. A prior preparation grant that ended at handoff or publication stays expired.

Validate maintainer feedback and other supplied findings through [Incorporate Feedback and Findings](../SKILL.md#incorporate-feedback-and-findings). That workflow establishes applicable fix confirmation and returns to this revision checkpoint rather than treating maintainer comments as authorization.

After authorization, use [Implement and Review](prepare-pull-requests.md#implement-and-review) for the selected revisions. The implementation review covers the complete revision delta and affected integration boundaries against the recorded baseline, not a fresh review of the entire pull request. Supply the selected feedback and settled decisions to the reviewer, and retain the shared [review method](prepare-pull-requests.md#review-contributions), including its independent-review default and disclosed self-review fallback. Unless explicitly waived, complete validation and this review before committing or handing back working tree changes, even when no commit was requested.

Apply both [upstream synchronization checkpoints](prepare-pull-requests.md#synchronize-with-upstream) within current authorization. Route any requested commit or history update through [Prepare Commits](prepare-pull-requests.md#prepare-commits). For a working-tree-only request, report any synchronization requiring uncovered history changes rather than treating the request as authority to perform them. Complete the applicable [readiness check](prepare-pull-requests.md#check-submission-readiness) and [handoff](../SKILL.md#hand-off-contributions) for the revised result. Do not reopen settled decisions without changed relevant content or materially new evidence, or turn the round into ongoing monitoring.

## Preserve Shared Pull Request History

Preserve a pull request branch’s published history by default once upstream review of the pull request has started or another contributor has pulled the branch. Add fixes as new commits and merge upstream when synchronization is needed, rather than amending, force-pushing, or rebasing for cleanup or conflict resolution. Conflict-only rewrites still disrupt incremental review and prevent existing reviewer checkouts from fast-forwarding.

Explicit user rewrite requests and the existing [single-commit title alignment authorization](prepare-pull-requests.md#align-single-commit-titles) remain supported through the resolved [commit workflow](../SKILL.md#compose-with-peers). Permission to edit a pull request alone does not authorize a rewrite. If repository requirements conflict with preservation, resolve that conflict before selecting an operation. All commit and publication gates remain unchanged.
