# Guidance Recovery

For each part of this skill’s guidance used by the selected workflow, determine whether it’s required, optional, or supporting. A reference is broken if its local target is missing, its destination is malformed, or an HTTP response reports the resource as missing or permanently unavailable. Treat guidance as stale when it has a broken reference or a verified conflict with the current interface or behavior. Follow any failure procedure the guidance defines. If it doesn’t define one, report the stale guidance and evidence, recommend updating this skill, and use the appropriate recovery below.

When required guidance is stale, use a complete available fallback or verify replacement guidance against authoritative evidence within the task’s boundaries. Ask before changing an explicitly selected version or another material task assumption. If no supported route remains, report the affected limitation and continue independent authorized work. An explicit procedural waiver under [Instruction Authority](../SKILL.md#instruction-authority) doesn’t supply missing evidence or establish that an omitted step succeeded. Stale optional or supporting guidance doesn’t stop the workflow.

Access restrictions, authentication problems, network failures, and HTTP server errors aren’t evidence that guidance is stale. For an ordinary technical failure, correct a demonstrated path or invocation mistake, make bounded retries, or use an equivalent method, but only if the target, authorized effects, authentication, and disclosure boundaries stay the same. Don’t evade denied access or a security control. Use the supported grant or correction process instead. The approval requirements for new dependencies, destinations, or broader effects still apply. If recovery doesn’t succeed, report the resource, attempted methods, exact error, and smallest corrective action. Don’t claim the affected step succeeded. Continue independent authorized work.

Never infer missing content or substitute an unverified location. Preserve scope, approval, mutation, and security boundaries.
