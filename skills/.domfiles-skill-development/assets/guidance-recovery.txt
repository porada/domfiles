# Guidance Recovery

Classify each part of this skill’s guidance used by the selected workflow as required, optional, or supporting. Treat missing local targets, malformed destinations, and HTTP responses that report a resource as missing or permanently unavailable as broken references. Broken references and verified conflicts with the current interface or behavior mean the guidance is stale. Use any failure response the guidance defines. Otherwise, report the stale guidance and evidence, recommend updating this skill, and follow the appropriate recovery below.

When required guidance is stale, use a complete available fallback or verify replacement guidance against authoritative evidence within the task’s boundaries. Ask before changing an explicitly selected version or another material task assumption. If no supported route remains, report the affected limitation and continue independent authorized work. An explicit procedural waiver under [Instruction Authority](../SKILL.md#instruction-authority) does not supply missing evidence or establish that an omitted step succeeded. Stale optional or supporting guidance does not stop the workflow.

Access restrictions, authentication problems, network failures, and HTTP server errors are not evidence of staleness. For ordinary technical failures, make bounded retries or use an equivalent method only while the target, authorized effects, authentication, and disclosure boundaries remain unchanged. Do not evade denied access or a security control. Use the supported grant or correction process instead. New dependencies, destinations, or broader effects retain their own approval requirements. If recovery is unsuccessful, report the resource, attempted methods, exact error, and smallest corrective action without claiming the affected step succeeded.

Never infer missing content or substitute an unverified location. Preserve scope, approval, mutation, and security boundaries.
